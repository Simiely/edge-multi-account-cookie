# Edge Multi-Account Cookie Switcher

> 安全的 Edge 多账号 Cookie 切换器 — 本地存储、密码锁保护，一键切换网站账号，支持 WebDAV 远程备份。
>
> **版本：** v2.11.7 | **架构：** Manifest V3 | **主题：** 珊瑚粉深色 | **协议：** MIT

---

### 简介

一款基于 **Manifest V3** 的 Edge/Chrome 浏览器扩展，让你在同一浏览器中**保存和切换多个网站账号**，无需反复登录退出。

Cookie 值明文存储（与浏览器自身 Cookies 数据库一致，避免加密膨胀超限导致切换失效）、密码锁保护、WebDAV 远程备份、纯原生 JS 零第三方依赖。**珊瑚粉深色主题 UI**（主色 `#FF9292`），弹窗采用 Gmail 式身份锚点 + 账号卡片流，设置页采用分区卡片式 + 状态概览栏。

> **稳定性机制（架构重点，改代码前必读）**：本扩展**所有 cookie 读写/切换操作都必须在 popup 页面上下文直调**，**严禁**放进 Service Worker 消息路由——Edge/Chrome 的 MV3 Service Worker 中 `chrome.cookies.getAll` 读不到浏览器主会话的 cookie（Chromium 官方将 SW 的 cookie 访问标记为 intentionally restricted），曾因 v2.9.0 把切换收口进 SW 导致"清除旧 cookie 失效 → 新旧会话混存 → 账号很快过期"的 P0 事故（v2.11.1 修复）。详见 [DEVELOPMENT.md §25/§37](./DEVELOPMENT.md)。

### 核心功能

| 功能 | 说明 |
|------|------|
| 🎨 **珊瑚粉主题** | 全新深色 UI（主色 `#FF9292`），弹窗身份锚点 + 账号卡片流，设置页分区卡片 + 状态栏 |
| 🔄 **一键切换** | 保存当前网站的 Cookie + localStorage，点击卡片即可切换到目标账号（**popup 直调**，兼容所有站点；清除采用"已知列表 + 快照"双保险，杜绝新旧会话混存） |
| 💾 **保存账号** | 自动抓取当前登录状态的 Cookie（含 httpOnly、Partitioned Cookie、子域）和 localStorage 数据；域 cookie 与 host-only cookie 完整保留 |
| 🗑️ **删除同步** | 删除采用墓碑标记——已删除账号不会因同步旧备份而复活，删除在下次同步时同步到其他设备；「清空本地」仅本机物理清空（不传播删除），下次同步可从远端恢复 |
| 🔐 **密码锁** | PBKDF2（60 万次迭代）验证 + 连续失败指数锁定；打开弹窗需输入密码 |
| 📦 **智能备份** | 有密码锁 → 导出/导入自动用锁密码加解密；无锁 → 弹窗输入口令；导入/恢复智能合并（同名账号自动取最新） |
| ☁️ **WebDAV 同步** | 「测试保存」连通即自动保存配置；「一键同步」先拉远端最新合并进本地、再上传合并后全量（双向取最新，远端固定保留最新 1 份；本地无数据时跳过上传，防止清空远端） |
| ⌨️ **快捷键** | `Alt+Shift+S` 快速打开弹窗 |
| 🖱️ **右键菜单** | 右键页面 → "清除此站点 Cookie 并重新登录"（已知列表 + 全量双保险） |

### 权限说明

| 权限 | 用途 |
|------|------|
| `cookies` | 读写网站登录 Cookie |
| `storage` | 本地加密存储账号数据（local + session） |
| `tabs` / `activeTab` | 获取当前标签页的域名与状态 |
| `scripting` | 读写页面 localStorage |
| `contextMenus` | 右键菜单 |
| `alarms` | 预留（历史：每日会话体检已随 v2.10.x 移除） |

扩展默认不申请任何网站权限，仅在点击弹窗时通过 `activeTab` 获得临时权限。WebDAV 服务器域名在配置时按需授权。

### 安装方法

1. 从 [Releases](https://github.com/Simiely/edge-multi-account-cookie/releases) 下载最新 ZIP
2. **解压**到任意目录（注意：Chrome 92+ / Edge 已不支持直接拖拽 zip/crx 安装，必须先解压成文件夹）
3. 打开 Edge 浏览器，进入 `edge://extensions/`（Chrome 为 `chrome://extensions/`）
4. 打开右上角的 **"开发人员模式"**
5. 点击 **"加载解压缩的扩展"**（Chrome 为"加载已解压的扩展程序"）
6. 选择**解压后的文件夹**（确保根目录含 `manifest.json`）
7. 若提示被拦截，请先在 设置 → 扩展 中打开「**允许来自其他应用商店的扩展**」并重启浏览器

### 使用方法

1. 登录你的网站账号
2. 按 `Alt+Shift+S` 打开扩展弹窗
3. 如果弹窗显示授权横幅，点击「授权访问此网站」
4. 输入账号名称，点击「保存账号」
5. 登录第二个账号，重复步骤 2-4
6. 之后在弹窗中点击账号卡片即可一键切换

> ⚠️ **注意**：切换账号时使用扩展的「切换到该账号」功能，不要使用网站自带的"退出登录"，否则已保存的 Cookie 会被服务器端作废。

### WebDAV 远程同步

1. 打开设置页 → 在「WebDAV 远程备份」卡片填写服务器 URL（**留空自动用默认服务器**）、用户名、密码
2. 点「🔌 测试保存」验证并保存配置（输入框内直接按回车也可触发；连通后配置自动保存，测试失败不会保存）
3. 点「🔄 一键同步」：先拉取远端最新备份智能合并进本地 → 再上传合并后的全量（同一账号自动取最新版本，双向收敛；远端固定保留最新 1 份）
4. 弹窗底部「🔄 同步」图标可快捷同步，无需进设置页

> 备份文件为 AES-GCM 密文，口令即 WebDAV 密码——即使服务器管理员也无法读取你的账号数据。

### 常见问题

**Q: 保存了 0 个 Cookie？**
A: 未获得当前网站的访问权限。弹窗顶部会显示授权按钮，点击「授权访问此网站」即可。

**Q: 点击"登录新账号"后还是登录状态？**
A: 更新到最新版本即可。

**Q: 密码锁能干什么？**
A: 开启后打开弹窗需输入密码，连续输错 5 次会锁定一段时间；Cookie 数据本地明文存储（与浏览器自身一致），备份/导出环节仍加密保护。

**Q: 导出备份需要输入密码吗？**
A: 设置了密码锁 → 自动用密码锁密码加密（无需输入）；未设锁 → 弹窗输入任意口令。导入同理：先自动用锁密码尝试，失败再弹窗输入。

**Q: 重装扩展后密码和账号数据还在吗？**
A: manifest 中加入了 `key` 字段，扩展 ID 固定，重装后数据保留。

**Q: 旧版本（v2.2 及更早）数据会丢失吗？**
A: 不会。首次打开新版本会自动迁移：既有 Cookie 自动加密、密码锁自动升级为更强的 PBKDF2 格式；旧备份文件导入时自动兼容旧迭代次数（10 万次）解密。

**Q: 之前切换后账号很快过期/需要重新登录，修复了吗？**
A: 已修复（v2.11.1 + v2.11.6）。① v2.11.1：根因是 v2.9.0 把切换操作收口到 Service Worker 执行，而 Edge 的 SW 中 `cookies.getAll` 读不到浏览器 cookie → 切换时旧 cookie 清不掉 → 新旧会话混存 → 服务端校验失败。现切换改回 popup 页面直调（与 v2.2 一致），并用"已知列表 + 快照"双保险清除。② v2.11.6：切换时**跳过已过期 cookie**（Chrome `cookies.set` 对过期 expirationDate 视为删除操作，写回会 set 失败触发整批回滚、或"写入即删除"导致登录 cookie 丢失）——未过期 cookie 全部正常写入。**如果仍遇到**：多半是账号数据已旧（服务端会话如 Keycloak 30min~10h TTL 早已失效），请在网站**登录成功后重新保存**该账号覆盖；切换时提示"⚠ N 个 Cookie 已过期未写入"即表示存在过期凭据。

**Q: 账号卡片上的绿点/红点是什么意思？**
A: 该功能（会话健康探测）已在 v2.10.x 移除——切换逻辑简化为「清→写→reload」，切换成功即视为成功，不再做服务端存活探测（探测依赖第三方 realm、跨域易误报，对核心功能无增益）。

**Q: WebDAV 保存后点「连接测试」还要输入密码？**
A: 不需要。已保存的配置会记住凭据，密码框留空时点「连接测试」会自动复用已保存的用户名/密码。仅当从未保存过配置时才需填写。

**Q: 清空数据后再同步，会把空数据传上去吗？**
A: 不会（v2.11.2 起兜底，v2.11.4 语义修正）。「清空本地账号数据」仅本机物理清空、不传播删除（删除单个账号才走墓碑跨设备同步）；同步上传前有兜底——本地无任何数据时跳过上传，杜绝把空备份覆盖到远端；远端有备份时同步会拉回恢复本地。

**Q: 从旧版本升级后同步，远端备份变小/变空了？**
A: 这是升级迁移坑（v2.11.2 → v2.11.4）。旧版本「清空」会留下墓碑（几 KB），升级后**未先清空本地**直接同步，本地墓碑会压过远端账号数据、把远端完整备份覆盖成小墓碑。**升级后请先「清空本地账号数据」，再点同步**（清空后本地无墓碑，同步会从远端拉回完整数据）。
